# Medical Foundation Model（医療基盤モデル）

## 一言で

**医療画像とテキストを扱う基盤モデル。** 汎用 CV と技術的には地続きだが、**データが外に出せない・モダリティが極端に多様・正解に専門医が要る・失敗のコストが非対称**という 4 つの制約が設計を強く規定する。本 wiki に取り込まれた範囲では、アプローチは **3 つの類型**に整理できる。

> 本ページの一次情報は [[sources/medgemma]] / [[sources/medgemma-1-5]] / [[sources/eva-x]] / [[sources/i-synmed]] / [[sources/mini-internvl]] の 5 件である。これを超える記述には ⚠ を付けた。

## 医療が汎用 CV と違う 4 点

| 制約 | 帰結 |
|---|---|
| **データを外に出せない** | プライバシー保護のため、**ローカル・オフライン実行**が要件になりうる。API 越しの巨大モデルが使えない場面がある |
| **モダリティが極端に多様** | X 線・CT・MRI・病理・皮膚・眼底で画像の性質がまったく違う。CT は HU という物理単位を持ち、MRI は相対値しか持たない |
| **正解に専門医が要る** | ラベルが高価。[[sources/medgemma]] は「粗いラベルは安価だが誤りを含む」という前提から出発する |
| **失敗のコストが非対称** | 見逃しと過剰診断で重みが違う。**指標が平均精度だけでは足りない** |

**この 4 点目が評価の設計を変える。** [[sources/medgemma]] の放射線科医評価は精度ではなく「**その報告書に従って正しい患者管理ができるか**」というルーブリックで採点している（後述）。

## 3 つの類型

| 型 | 代表 | 出発点 | 規模 | 特徴 |
|---|---|---|---|---|
| **単一モダリティ特化 SSL** | [[entities/eva-x]] | EVA-02 / MIM | **6M〜22M** | 胸部 X 線に絞る。**極小でも SOTA**（EVA-X-Ti 6M で CXR14 mAUC 82.4） |
| **合成データ SSL** | [[entities/i-synmed]] | DDPM + DINO | — | **合成 X 線 10 万枚**で事前学習。実画像事前学習と同等（肺炎 95.0%） |
| **汎用基盤モデルのドメイン適応** | **[[entities/medgemma]]** / [[entities/mini-internvl]] | Gemma 3 + SigLIP / InternVL | **400M〜27B** | **汎用性能を保ったまま**医療を足す。多モダリティを 1 モデルで兼任 |

### 型の選び方 — 深さか広さか

**同じ「胸部 X 線を読む」でも、[[entities/eva-x]] は 6M パラメータで、[[entities/medgemma]] は 4,000M である。** 600 倍以上の開きがある。EVA-X は胸部 X 線 1 つに絞って MIM で表現を作り込むのに対し、MedGemma は放射線・病理・皮膚・眼底の 4 領域を兼任し、さらにテキストで推論し報告書まで書く。

**直接比較した研究は本 wiki の範囲にはない** ⚠ が、選択の軸ははっきりしている。

- **1 モダリティ・1 タスクで最高精度が要り、エッジで動かしたい** → 特化 SSL
- **複数モダリティを横断し、テキストと組み合わせ、微調整の出発点が欲しい** → 汎用のドメイン適応

同じトレードオフは [[entities/medsiglip]] の linear probe 結果にも現れる。**最小の 64 枚では胸部 X 線専用の CXR Foundation（ELIXR）に負け、512 枚以降で逆転する**。多領域兼任の代償が極少データ領域に出ている。

## 「汎用性を壊さずに専門性を足す」ための手口

**これが本 wiki にとって最も実務的な収穫である。** [[sources/medgemma]] は具体的な数値とともに手口を公開している。

| 手口 | 具体 | 効果 |
|---|---|---|
| **元データを残して低い重みで混ぜる** | 視覚エンコーダ: WebLI + **医療 2%** / デコーダ事前学習: Gemma 3 混合 + **医療 10%** | MMLU Pro -4.5pt、Global MMLU Lite **+1.0pt**（劣化がほぼない） |
| **不要な段階では足さない** | デコーダ事前学習で医療テキストを追加しない（元の混合が既に汎用・大規模だから） | — |
| **SFT でなく RL** | マルチモーダル後訓練はすべて RL | 「SFT より汎化する」と報告 |
| **既に作った部品を凍結する** | [[entities/medgemma-1-5]] は MedSigLIP を凍結し言語デコーダのみ更新 | 3D 対応を視覚側でなく言語側の問題に切り分けられる |
| **モダリティ別の補助教師** | 1.5 では CT / MRI / 病理それぞれに教師を訓練して蒸留 | — |

> **これは [[concepts/knowledge-distillation]]（教師の知識を写す）や [[concepts/parameter-efficient-fine-tuning]]（更新するパラメータを絞る）とは別系統の「忘却を防ぐ」実務**である。パラメータを凍らせるのでも蒸留するのでもなく、**訓練データの配合比で制御する**。

**ただし規模には限界がある。** [[entities/medgemma-1-5]] では 3D と WSI を詰め込んだ結果、**MMLU Pro が Gemma 3 4B 比で -9.8pt** まで落ちた。論文自身が「**4B パラメータのクラスにおける明確なトレードオフ**」と認めている。配合比の工夫で守れる範囲は、モデル容量と追加する能力の量に依存する。

## 汎用 MLLM vs 医療特化 — 現在地

[[sources/medgemma-1-5]] は同サイズの汎用 MLLM である [[entities/qwen3-vl]] 4B と横並びの表を出しており、**本 wiki で初めて「同一パラメータ数での汎用 vs 特化」の一次情報**が入った。結果は綺麗な非対称だった。

| 領域 | 勝者 | 例 |
|---|---|---|
| **テキストの医学知識** | **汎用**（Qwen3-VL） | MedQA 76.8 vs 69.1、MMLU Med 78.3 vs 69.7、EHRNoteQA 90.6 vs 80.4 |
| **医療画像の解釈** | **特化**（MedGemma 1.5） | **すべての視覚タスク**。EyePACS 76.8 vs 41.9、PathMCQA 70.0 vs 41.8、局在化 IoU 38.0 vs 8.7 |

**説明は素直につく。医学知識は教科書や Web にテキストとして大量に存在し汎用の事前学習で吸収できるが、眼底写真や病理パッチのラベル付きデータは Web にない。**

同じ構図は [[sources/medgemma]] のモダリティ別の結果にも現れる。

| モダリティ | MedGemma 4B | Gemini 2.5 Pro | 解釈 |
|---|---|---|---|
| 眼底（EyePACS） | **64.9** | 27.7 | Web に眼底写真は少ない → 特化が圧勝 |
| 病理（PathMCQA） | **69.8** | 42.7 | 同上 |
| 皮膚（US-Derm MCQA） | 71.8 | **81.0** | **Web に皮膚画像は豊富** → 汎用が勝つ |

> **ドメイン特化の利得は、そのモダリティの Web 上での希少性と相関する。** これは医療に限らず、ドメイン適応一般に効く経験則として読める。

**規模で埋まらない差もある。** [[sources/medgemma-1-5]] Appendix A の CT-RATE（分布外の 3D CT）では **MedGemma 1.5 4B が 26.9、Gemini 3.0 Flash が 8.5** と 3 倍以上の差がついた。3D 医療画像という領域では、モデル規模より**前処理と訓練データの適合**が支配的である。

## 高次元画像をどう扱うか

3D CT/MRI と病理 WSI は、そのままでは 2D の視覚エンコーダに入らない。[[entities/medgemma-1-5]] が採った解は**アーキテクチャを変えず前処理と長コンテキストで解く**というものだった。

| 対象 | 変換 | トークン数 |
|---|---|---|
| **3D CT / MRI** | 軸位断 2D スライス列（最大 **85** 枚、等間隔サンプル） | **21,760** |
| **病理 WSI** | 組織領域から 896² パッチ（最大 **126** 枚、空間順序を保存） | **32,256** |

**[[entities/gemma-3]] の 128K 長コンテキストがなければ成立しない設計**である。本 wiki では長コンテキストを「長い文書を読む」文脈で記述してきたが、ここでは**3D ボリュームを流し込む器**として使われている。アーキテクチャの新規性ではなく、**既存の容量の使い道の発明**として読むべき例である。

**物理単位の有無で処理が分かれる**点も重要。CT は HU（Hounsfield Unit）という絶対的な物理単位を持つので **3 つの読影ウィンドウを RGB チャネルに写像**できるが、MRI は相対値しか持たないのでウィンドウ処理をせず volume 単位の min-max 正規化で R=G=B にする。**「画像」と一括りにできない**のが医療の難しさである。

**代償**: スライスを最大 85 枚まで等間隔サンプルするので、**薄いスライスでしか見えない小病変は原理的に落ちうる**。「本当の 3D」ではない。

## 評価の難しさ

**自動指標だけでは足りない**、というのが本領域の共通認識である。

**(1) ベンチマークが飽和している。** [[sources/medgemma]] §8 は「**一部のベンチマークはモデルの性能の点で飽和に近く、改善のための余地が最小限であり、進歩の測定を妨げている**」と明記する。実際 MedQA では MedGemma 27B が 87.7 まで来ているが、飽和していない MedXpertQA では 25.7 で o3 の 54.6 の半分以下になる。**飽和したベンチマークが差を隠している。**

**(2) 指標が臨床的意味を持たない。** RadGraph F1 が 29.5 と言われても、それが臨床的に安全かは分からない。

**(3) だから専門医の目を入れる。** [[sources/medgemma]] Appendix A のルーブリックは秀逸で、採点軸を**所見の一致度ではなく「正しい患者管理に至るか」**に置いている。

| スコア | 意味 |
|---|---|
| AI >> Original | **AI は正しい患者管理をもたらし、元の報告書はもたらさない** |
| AI > / ~ / < Original | **どちらも同じ正しい患者管理をもたらす** |
| AI << Original | **元の報告書は正しい患者管理をもたらし、AI はもたらさない** |
| X | どちらも正しい患者管理をもたらさない |

この設計のおかげで「81% が同等以上」という数字が解釈可能になり、同時に**残り約 18% は AI に従うと患者管理を誤る**ことも読み取れる。しかも**異常例の方が正常例より悪い**——臨床的に価値があるのはまさに異常例である。

**(4) それでも限界は残る。** この評価は**放射線科医 1 名・非盲検**で行われている。[[entities/medgemma-1-5]] に至っては、新能力について**これに相当する系統的な人間評価がない**。

**(5) 幻覚は代表図にすら写る。** [[sources/medgemma-1-5]] の図3 は論文が自ら選んだ肝腫瘍の成功例だが、放射線科医は「**実質的な肝内胆管拡張は明らかでない**」と不同意を示している。腫瘍の存在も性状も当てたうえで、もっともらしい所見を 1 つ足してしまう。

## 開かれていることの意味

医療では「性能が高いモデルを API で呼ぶ」が必ずしも選択肢にならない。[[sources/medgemma]] §8 が挙げる 4 条件は本領域固有の要件として押さえる価値がある。

| 条件 | 理由 |
|---|---|
| **凍結されたモデル** | API 越しのモデルは黙って更新されうるので、**規制対象の医療機器としての検証が成立しない** |
| **訓練・推論コスト** | 4B なら 1 GPU |
| **ローカル・オフライン実行** | **患者データを外部に出せない** |
| **適応に対する完全な制御** | 微調整・量子化・蒸留の自由 |

**ただし「オープンモデル」は「オープンな訓練」ではない。** MedGemma の訓練データの中核（Internal histopathology 3,260 万パッチ、CXR-IND1 60 万、CT/MRI Dataset 1 など）は**すべて非公開**で、重みだけが公開されている。[[entities/clip]] の WIT-400M や [[entities/dinov3]] の LVD-1689M と同じ構図だが、**医療ではデータの偏りが患者集団の偏りに直結する**ため重みが違う ⚠。[[entities/eva-x]] のページでも「CXR14/CheXpert/MIMIC は特定人口統計に偏る」ことが弱点として記録されている。

## 現在地

本 wiki に取り込まれた範囲では:

1. **汎用基盤モデルのドメイン適応が主流になりつつある**。1 つのモデルで多モダリティ + テキスト + 微調整の出発点を兼ねられる
2. **単一モダリティ特化 SSL は消えていない**。極小モデルで動く必要がある場面で優位が残る
3. **合成データは制約への回答として有効**だが、本 wiki の一次情報は [[sources/i-synmed]] 1 件にとどまる ⚠
4. **評価が追いついていない**。ベンチマークは飽和し、人間評価はコストが高く、幻覚の検出手段が確立していない
