# MedGemma: 医療の視覚–言語基盤モデル

> 原典: [[translations/medgemma]] ・ `raw/papers/MedGemma Technical Report.md`
> 著者: Google Research + Google DeepMind（責任著者: Lin Yan, Daniel Golden, Andrew Sellergren）
> 出典: arXiv:2507.05201
> モデル: <https://goo.gle/medgemma>（Health AI Developer Foundations）

## 一言まとめ

**[[entities/gemma-3]] と [[entities/siglip]] のアーキテクチャを 1 ミリも変えず、医療データの「混ぜ方」だけ**で、同サイズの汎用モデルを大きく上回り、桁違いに大きなモデルに迫るモデル群を作った。加えて視覚エンコーダを **MedSigLIP** として単独公開した。

## 背景と問題意識

### 本当の論点は「精度」ではなく「開いていること」

「汎用 LMM は医学の機微を掴めない」という動機づけ自体は目新しくない。本レポートの読みどころは、**Gemini のような API 経由の大規模モデルが既にあるのに、なぜ開いた 4B なのか**を §8 で明示的に答えている点にある。論文が挙げる 4 条件は実務的で説得力がある。

| 条件 | 意味 |
|---|---|
| **凍結されたモデル** | 文書化と信頼性のため。API 越しのモデルは黙って更新されうるので、**規制対象の医療機器としての検証が成立しない** |
| **訓練・推論コストへの感度** | 4B なら 1 枚の GPU に載る |
| **ローカル・オフライン実行** | **患者データを外部に出せない**という医療特有の制約への直接的な回答 |
| **適応に対する完全な制御** | 微調整・量子化・蒸留を自由にできる |

実際、表の数字だけを見れば **Gemini 2.5 Flash が MedQA で 92.0、MedGemma 4B が 64.4** と大差がある。それでも 4B を作る理由がこの 4 条件であり、**「性能で勝つ」ではなく「性能を諦めずに制約を満たす」**という設計目標として読むのが正しい。この整理は [[concepts/foundation-model]] の「基盤モデルの必要要件」の議論に、医療という具体的な制約条件を与えるものである。

### 何を捨てたか

Med-Gemini との差分として、**3D ボリュームとゲノムデータを外し、2D 医療画像に絞った**ことが明記されている（この制約を外すのが後継の [[sources/medgemma-1-5]] である）。また **PathVQA と MedVQA はデータ品質の問題を理由に訓練データから除外**しており、既存の医療 VQA ベンチマークの信頼性への疑義が示されている。

## 提案手法

### アーキテクチャは Gemma 3 そのまま

> **MedGemma のモデルアーキテクチャは Gemma 3 に従い、既存の Gemma の基盤すべてと互換性がある。**

これが本レポートの最も重要な一文である。視覚エンコーダは SigLIP-400M、入力 896×896、5:1 の local:global attention による 128K 文脈、SentencePiece 262K 語彙——**すべて [[entities/gemma-3]] のまま**。変えたのは訓練データと前処理だけである。

したがって以下は**すべて「何をどれだけ混ぜたか」の話**になる。

### 3 段構えの訓練

**(1) 視覚エンコーダ強化 → これが MedSigLIP になる**

SigLIP-400M を **3,300 万を超える医療の画像–テキスト対**で微調整する。内訳は各種モダリティから 63.5 万、**組織病理学パッチが 3,260 万**——つまり 98% が病理である。

ここで肝心なのが混合比である。

> **SigLIP の既存の性能を保持するため、その元の訓練データ（例: WebLI）を残し、医療データを 2% の重みで訓練に混合した。**

**わずか 2%。** 汎用性を壊さずに専門性を足すという目的に対して、医療データを主役にしないという判断が明示的に取られている。

**(2) マルチモーダルデコーダ事前学習**

エンコーダが変わったので言語モデルを再適応させる。ここでも**医療データは 10% の重み**で、元の Gemma 3 混合（テキスト + インターリーブ画像）を残したまま約 5 エポック。**この段階で医療のテキストのみのデータは追加していない**——「元の Gemma 3 混合が既に汎用的かつ大規模だったから」というのが理由である。

**(3) 後訓練（蒸留 + RL）**

蒸留では大規模 IT 教師から医療テキストを学ぶ。注目すべきは次の一文。

> **マルチモーダルの訓練については、教師ありの微調整（SFT）と比較して RL の方がより良い汎化を可能にすることを見出したため、マルチモーダルの後訓練はすべて RL を介して行った。**

**マルチモーダルは SFT より RL の方が汎化する**という経験則が、実装上の決定として採用されている。理由の説明はないが、医療画像の「正解レポート」が一意でない（同じ所見に対する記述の自由度が高い）ことを考えると、トークン一致を強制する SFT が過剰に強い制約になる、という解釈は成り立つ。

### 非自明な前処理: CT を RGB に押し込む

CT の画素値は **HU（Hounsfield Unit）** という物理単位で、-1000（空気）から +1000 超（骨）まで広い範囲を持つ。一方 SigLIP はチャネルあたり 256 階調しか扱えない。そこで:

**表**: CT の 3 ウィンドウを RGB チャネルに写像する（原典 §2.1.2）

| チャネル | 対象 | window-width | window-level |
|---|---|---|---|
| R | 骨と肺 | 2250 | -100 |
| G | 軟部組織 | 350 | 40 |
| B | 脳 | 80 | 40 |

> **補足: ウィンドウ処理（windowing）** — CT の読影で放射線科医が日常的に行う操作で、HU の全範囲のうち見たい組織の範囲だけを切り出して 256 階調に引き伸ばすこと。window-level が中心値、window-width が幅。**放射線科医が「肺野条件」「縦隔条件」と切り替えながら読むのと同じことを、3 チャネルに同時に詰め込んでいる**。カラー画像の R/G/B という枠が、たまたま「3 つの読影条件」を運ぶ器として再利用されている。

### 解像度の非対称: 896² と 448² は同じ重み

Gemma 3 との互換性のため MedGemma 4B の画像エンコーダは 896² だが、**医療タスクは 448² でも十分機能した**（表15）ため、**公開される MedSigLIP は 448²** になっている。そして両者は:

> **同じモデル重みを共有しており、唯一の違いは、より低い解像度からのより少ない入力パッチで動作するように位置埋め込みをダウンサンプルしていることだけ。**

重みが同一なので、**同じモデルを解像度だけ切り替えて使える**。計算量は約 1/4 になる。医療画像は高解像度が要ると思われがちだが、少なくとも本論文の評価範囲では 448² で足りたという知見自体が有用である。

## 実験結果と知見

### テキスト QA — ベースモデルとの差が大きい

**表**: テキストのみの医療ベンチマーク（原典 表3 より抜粋）

| Model | MedQA | MedMCQA | PubMedQA | MMLU Prof. Medicine |
|---|---|---|---|---|
| **MedGemma 4B** | **64.4** | **55.7** | 73.4 | 76.8 |
| Gemma 3 4B | 50.7 | 45.4 | 68.4 | 65.4 |
| **MedGemma 27B**（test-time scaling あり） | **87.7** | **74.2** | 76.8 | 93.4 |
| Gemma 3 27B | 74.9 | 62.6 | 73.4 | 85.7 |
| OpenBioLLM 70B | 78.2 | 74.0 | 79.0 | 93.8 |
| Gemini 2.5 Flash | 92.0 | 79.7 | 76.2 | 96.0 |

**MedQA で +13.7pt（4B）/ +12.8pt（27B）**。27B は 70B の医療特化オープンモデルを上回る。ただし Gemini 2.5 Flash には届かない。

### MedXpertQA が示す限界

論文は都合の悪い数字も載せている。

| Type | MedGemma 4B | MedGemma 27B | Gemini 2.5 Pro | o3 |
|---|---|---|---|---|
| Text-only | 14.2 | 25.7 | 43.1 | **54.6** |
| Multi-modal | 24.4 | N/A | 58.9 | **67.5** |

**MedXpertQA（難度の高い分布外ベンチマーク）では 27B でも 25.7 で、o3 の 54.6 の半分以下。** MedQA のような試験問題形式で稼げても、真に難しい推論では大規模モデルとの差が開いたままである。**ベンチマークの飽和に隠れていた差が、飽和していないベンチマークで露出する**という構図であり、論文自身が §8 で「一部のベンチマークは飽和に近く進歩の測定を妨げている」と書いていることと呼応する。

### 画像分類 — ここが最も差が出る

**表**: 胸部 X 線の所見分類（マクロ F1、原典 表7）

| Dataset | MedGemma 4B | Gemma 3 4B | Gemma 3 27B | Gemini 2.5 Pro | SOTA |
|---|---|---|---|---|---|
| MIMIC-CXR (Med-Gemini test) | **88.9** | 81.2 | 71.7 | 85.8 | 90.7（Med-Gemini） |
| CheXpert (OOD) | **48.1** | 32.6 | 26.2 | 37.0 | 49.0（RadVLM） |
| CXR14 (OOD) | **50.1** | 32.0 | 31.4 | 39.2 | 46.7（Med-Gemini） |

**分布外の CheXpert / CXR14 で 4B が Gemini 2.5 Pro を 11〜13pt 上回る。** テキストでは大きく負けていた相手に、視覚ではっきり勝つ。これが「ドメイン特化の視覚エンコーダを持つこと」の効果である。

**表**: 他モダリティの分類精度（原典 表8）

| Modality | Dataset | MedGemma 4B | Gemma 3 4B | Gemini 2.5 Pro |
|---|---|---|---|---|
| 組織病理 | PathMCQA | **69.8** | 37.1 | 42.7 |
| 皮膚科 | US-Derm MCQA | 71.8 | 52.5 | **81.0** |
| 眼底 | EyePACS | **64.9** | 14.4 | 27.7 |

**EyePACS（糖尿病網膜症のグレーディング）で 14.4 → 64.9 という劇的な差**が出る一方、**皮膚科では Gemini 2.5 Pro に負けている**。おそらく皮膚病変の画像は Web 上に豊富で汎用モデルが既に見ているが、眼底写真と病理パッチはそうでない、という説明がつく。**「どのモダリティでドメイン特化が効くか」はデータの Web 上での希少性と相関している**、と読める。

### 放射線科医による評価 — 本論文で最も重い結果

<figure>

![](../../raw/assets/medgemma/fig4.png)

<figcaption>図4（再掲）: MIMIC-CXR の 306 症例について、認定を受けた胸部放射線科医 1 名が AI 生成レポートと元のレポートを比較した選好ラベルの分布。上が正常例（99 件）、中が異常例（207 件）、下が全体（306 件）。青系が AI 優位、灰色が同等、桃・橙が元レポート優位、黒が「どちらも不適切」。</figcaption>
</figure>

論文が掲げる数字は「**全症例を通して、MedGemma の胸部 X 線レポートの 81% が元のレポートと比較して同等または優れた臨床判断をもたらした**」である。ここでルーブリック（Appendix 表A1）を正確に読む必要がある。

- `AI >> Original` = **AI は正しい患者管理をもたらし、元のレポートはもたらさない**
- `AI > / ~ / < Original` = **どちらも同じ正しい患者管理をもたらす**（所見の captureの多寡が違うだけ）
- `AI << Original` = **元のレポートは正しい患者管理をもたらし、AI のレポートはもたらさない**
- `X` = どちらも正しい患者管理をもたらさない

つまり **81% = 100% − (AI << Original) − X**。裏を返すと:

> **約 18% の症例で、AI のレポートに従うと患者管理を誤る。**

しかも図から読める通り、**異常例（207 件）の方が正常例（99 件）より悪い**。正常な画像で「異常なし」と書くのは易しく、異常がある画像で正しい所見を挙げるのが難しい——という当たり前の非対称が数字に出ている。**臨床的に価値があるのはまさに後者**である。

**加えて方法論上の重大な限界がある。** 論文が正直に書いている通り:

> 評価者は評価において中立を保つよう求められたが、**どちらのレポートが元の放射線科医のものでどちらが AI システムのものかについては盲検化されていなかった**。

さらに **評価者は 1 名のみ**である。81% という数字は、非盲検・単一評価者の条件下で得られたものとして読む必要がある。

> それでも本 wiki 的にはこの評価を高く買いたい。[[sources/l2rw]] の ingest でも触れた通り、**自動指標だけで押し切らずに専門家の目を入れ、しかも自分に不利な分布まで図で公開している**論文は多くない。RadGraph F1 が 29.5（表10）という数字だけを見せられても臨床的な意味は分からないが、この図は「18% は危ない」という解釈可能な形を与えている。

### 微調整すると特化 SOTA に届く

**表**: 微調整の効果（原典 表13）

| Task | Dataset | Metric | 即応 | 微調整後 | SOTA |
|---|---|---|---|---|---|
| CXR レポート生成 | MIMIC-CXR | RadGraph F1 | 29.5 | **30.3** | 30.0（MedVersa） |
| 気胸分類 | SIIM-ACR (OOD) | F1 | 59.7 | **71.5** | 72.5（Unichest FT） |
| 組織病理分類 | CRC100k (OOD) | Weighted F1 | **32.8** | **94.5** | 97.3（Virchow） |

**CRC100k の 32.8 → 94.5 が圧巻**である。即応では使い物にならないが、微調整すれば特化モデルに肉薄する。**「基盤モデルは出発点であって完成品ではない」**という主張の最も強い実証で、論文が §8 で繰り返す「開かれていることの価値」と直結する。

EHR では RL 調整で EHRQA が **86.3 → 93.6**（誤りが約 50% 減）。Appendix D の図A3 を見ると、伸びの大半は **Observation (dependent)** カテゴリが約 43% → 約 84% と倍増したことによる。「ある薬の初回処方の後で最初に記録された疼痛スコアは何か」といった**複数のレコードを時系列で結ぶ質問**であり、まさに RL で伸びそうな種類のタスクである。

### 汎用性能はほとんど落ちていない

**表**: 汎用ベンチマーク（原典 表12）

| Benchmark | MedGemma 4B | Gemma 3 4B | MedGemma 27B | Gemma 3 27B |
|---|---|---|---|---|
| MMLU Pro | 39.1 | 43.6 | 60.2 | 67.5 |
| Global MMLU Lite | **55.5** | 54.5 | 74.5 | 75.1 |
| MMMU (val) | 47.3 | 48.8 | N/A | 64.9 |

**Global MMLU Lite では 4B がむしろ上回っている。** MMLU Pro で 27B が -7.3pt 落ちるのが最大の劣化だが、医療特化モデルとしては十分小さい。**2% / 10% という控えめな混合比が効いている**ことの傍証と読める。

### MedSigLIP — 低解像度で ELIXR を上回る

ゼロショットの胸部 X 線で **CXR Foundation（ELIXR ベース）を平均 2.0% 上回る**。しかも **448² 対 1280²** という解像度の不利を背負い、かつ胸部 X 線専用ではなく多領域兼任でこれを達成している。

## 限界・批判的視点

**論文自身が認めている点**

- **ベンチマークが飽和に近く、進歩の測定を妨げている**（§8）。自動ベンチは実世界の有用性検証の第一歩にすぎない
- MedGemma 27B マルチモーダルの評価は**進行中**で、Appendix F は予備結果にとどまる
- 放射線科医評価は**非盲検**（§3.5）

**本 wiki の視点から見た限界**

- **再現不可能である**。訓練データの中核（Internal histopathology 3,260 万パッチ、Internal dermatology 5.1 万枚、CT-US1、MRI-US1）が**すべて非公開**で、公開されているのは重みだけ。**「オープンモデル」だが「オープンな訓練」ではない**。[[entities/dinov3]] の LVD-1689M や [[entities/clip]] の WIT-400M が非公開なのと同じ構図だが、医療では**データの偏りが患者集団の偏りに直結する**ため重みが違う。
- **MedXpertQA の差が縮まっていない**。o3 の半分以下という数字は、「小さく開いたモデルで足りる」という主張の適用範囲を限定する。
- **単一モダリティ特化との住み分けが未検証**。本 wiki の [[entities/eva-x]] は胸部 X 線に絞って **6M〜22M パラメータで CXR14 mAUC 82〜83** を出す。MedGemma 4B は 4,000M で多領域を兼任する。**同じベンチマークでの直接比較がなく、「多領域を 1 つのモデルで担う」ことの費用対効果は本論文からは判断できない**。
- **27B マルチモーダルは 27B テキストより弱い**（Appendix F、MedQA 85.3 vs 87.7、AfriMed-QA 72.0 vs 84.0）。マルチモーダル化がテキスト性能を削っており、**「両方できる 1 モデル」の代償**が可視化されている。

## 既存 wiki との接続

**本モデルは既存ページの真上に乗っている。** [[entities/gemma-3]]（Gemma 3 4B / 27B、5:1 attention、128K 文脈）と [[entities/siglip]]（sigmoid 損失、400M）はどちらも ingest 済みで、MedGemma はその**差分だけで記述できる**珍しい論文である。

**「汎用性を壊さずに専門性を足す」という主題**は、本 wiki で初めて一次情報が入る領域である。手口は 3 つに整理できる。

| 手口 | 具体 | 効果の確認 |
|---|---|---|
| **元データを残して低い重みで混ぜる** | WebLI + 医療 2%、Gemma 3 混合 + 医療 10% | MMLU Pro -4.5pt / Global MMLU Lite +1.0pt に留まる |
| **不要な段階で足さない** | デコーダ事前学習で医療テキストを追加しない | — |
| **SFT でなく RL** | マルチモーダル後訓練はすべて RL | 「より良い汎化」と報告 |

これは [[concepts/knowledge-distillation]]（教師の知識を写す）や [[concepts/parameter-efficient-fine-tuning]]（更新するパラメータを絞る）とは**別系統の「忘却を防ぐ」実務**であり、[[concepts/medical-foundation-model]] に整理した。

**[[entities/mini-internvl]] のドメイン適応と同じ問題設定**でもある。Mini-InternVL は InternVL に対して自律走行 / 医療 / リモートセンシングの 3 領域を VQA 形式に統一して適応させたが、MedGemma は医療 1 領域に絞って**視覚エンコーダ自体を作り直す**ところまで踏み込んでいる。

## 用語と略称

- **MedGemma** = 本論文の医療視覚–言語基盤モデル。4B マルチモーダル / 27B テキスト / 27B マルチモーダルの 3 変種
- **MedSigLIP** = MedGemma の視覚エンコーダを単独公開したもの。SigLIP-400M 由来、448²
- **HAI-DEF** = Health AI Developer Foundations。Google の医療 AI 基盤モデル群の総称
- **LMM** = Large Multimodal Model（大規模マルチモーダルモデル）
- **IT teacher** = instruction-tuned teacher。蒸留元の指示調整済み大規模モデル
- **MedQA** = USMLE（米国医師国家試験）形式の問題。**MedMCQA** はインドの医学入学試験、**AfriMed-QA** は汎アフリカ、**MedExpQA** はスペインの研修医試験
- **PubMedQA** = PubMed 抄録から作られた生物医学 QA。**HealthSearchQA / LiveQA** は消費者向け健康質問
- **MedXpertQA** = 難度の高い分布外の医療ベンチマーク。テキストとマルチモーダルの両方がある
- **AgentClinic** = 模擬患者エージェントと対話して診断に至るエージェント評価ベンチマーク
- **CXR** = Chest X-Ray（胸部 X 線）。**MIMIC-CXR** は MIT の大規模 CXR + レポートデータ、**CheXpert** は Stanford、**CXR14** は NIH
- **EyePACS** = 糖尿病網膜症のグレーディング用眼底画像データセット
- **PAD-UFES-20** = 皮膚病変の 6 クラス分類データセット
- **SLAKE / VQA-RAD** = 医療 VQA の標準ベンチマーク
- **PathMCQA / US-Derm MCQA** = 病理・皮膚科の多肢選択評価（内部データ）
- **RadGraph F1** = 生成レポートから抽出した所見のグラフ表現を正解と比較する指標。**レポートのスタイルに敏感**
- **ELIXR** = CXR Foundation モデルの基礎になっている胸部 X 線の埋め込み手法
- **linear probe（データ効率的分類）** = エンコーダを凍結し、埋め込みの上にロジスティック回帰など線形分類器だけを訓練して表現の質を測る評価。[[concepts/knn-evaluation-protocol]] と同系統の凍結特徴量評価
- **SAGA** = ロジスティック回帰の最適化ソルバ
- **test-time scaling** = 推論時に計算量を増やして精度を上げる手法（複数サンプルの多数決など）
- **HU（Hounsfield Unit）** = CT の画素値の物理単位。水が 0、空気が -1000、骨が +1000 超
- **window-width / window-level** = CT のウィンドウ処理の幅と中心値
- **WebLI** = SigLIP / PaLI 系の Web 画像–テキスト事前学習データ（Google 内部）
- **SIIM-ACR Pneumothorax / CRC100k** = 気胸分類・大腸組織病理分類の外部ベンチマーク
- **Chest ImaGenome** = 胸部 X 線の解剖学的バウンディングボックスを持つデータセット（27B マルチモーダルで使用）
- **FHIR / Synthea** = 医療情報交換の標準規格 / それに基づく合成患者記録の生成器（EHRQA の基）
